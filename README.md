# 数据监控台 · Data Monitor

> **一句话:告诉它"盯住这些数",它自动去采、自动比对、自动告诉你"哪儿涨了、哪儿跌了、哪儿出事了"。**
>
> 出事了**主动推送**到你的企业微信 / 钉钉 / 邮箱 —— 不用你天天去查。

**零依赖**:只用 Node 内置模块。没有 `node_modules`、没有 `package.json`、无需构建。
**可交付**:打包后约 139 KB,双击 `start.bat` 就能跑,不需要客户懂技术。

---

## 一、三种用法

### A. 交互式控制台 ⭐ 给人用

```bash
node server.mjs          # 启动服务,自动打开 http://127.0.0.1:4210/
```

**界面上每个按钮都是真的**(不是静态展示):

| 界面元素 | 实际行为 |
|---|---|
| **刷新数据** | 调 `POST /api/run` **真的重新采集**,按钮变「采集中…」,完成 toast 报结果 |
| 行内 **重采** | 只重采这一个目标 |
| **KPI 卡 / 筛选 chips** | 真的过滤表格(全部 / 有变化 / 告警 / 失败) |
| **搜索框** | 按 名称 / ID / 地址 实时过滤 |
| **表头** | 点击排序 |
| **点击表格行** | 右侧抽屉:该目标**历史走势图 + 全部历史记录** |
| **目标管理** | 新增 / 编辑 / 删除目标,**直接写入 config.json** |
| **先测一下能否取到值** | 保存前先验证提取规则能不能真的取到值 |
| **通知推送** | 配置推送渠道 + **一键发送测试通知** |
| **导出 CSV / JSON** | 真实下载文件 |
| **自动刷新** | 每 60 秒自动采集 |

### B. 命令行 / 定时任务

```bash
node monitor.mjs          # 采集一次 + 生成静态 HTML 报告 + 按配置推送通知
node monitor.mjs --json   # 额外输出机器可读 JSON
```

**退出码:** `0` 正常 ｜ `1` 有告警 ｜ `2` 有采集失败

### C. 一键启动(给不懂技术的客户)

| 文件 | 作用 |
|---|---|
| `start.bat` | 双击启动服务并自动打开浏览器(检查 Node 是否安装) |
| `install-autostart.bat` | 注册开机自启(静默后台运行) |
| `uninstall-autostart.bat` | 取消开机自启 |
| `install-daily-task.bat` | 注册每天早上 8:00 自动采集 + 推送通知 |
| `start.sh` | macOS / Linux 版启动脚本 |

> ⚠️ **编码经验**:`.bat` 全部是**纯 ASCII**。因为 cmd.exe 按系统代码页(中文机为 GBK)读批处理文件,
> UTF-8 的中文会把换行都吃掉导致脚本崩坏 —— 一个 .bat 无法同时兼容 GBK 与 UTF-8 控制台,
> 所以启动器一律用 ASCII,中文说明放进 `客户使用说明.txt`。

## 二、它能监控什么

**任何公开数据源**,只要能用下面 4 种方式之一取到"你关心的那个数":

| 提取方式 | 适用场景 | 配置示例 |
|---|---|---|
| `json` | 公开 API(最常见) | `{"type":"json","path":"current.temperature_2m"}` |
| `regex` | 网页 / 大文档里抠一个值 | `{"type":"regex","pattern":"\"latest\"\\s*:\\s*\"([^\"]+)\""}` |
| `length` | 判断页面变长 / 变短 | `{"type":"length"}` |
| `text` | 判断整页是否被改过(改版监控) | `{"type":"text"}` |

**典型用途:** 竞品价格 / 库存 / 销量 · 行业榜单排名 · 官网改版与新版本发布 · 政策招标公告 · 自家产品指标波动。

## 三、配置(客户只需要改这一个文件)

```json
{
  "name": "某某公司 · 竞品监控",
  "targets": [
    {
      "id": "price-a",
      "label": "竞品A 官方售价",
      "url": "https://example.com/api/price",
      "extract": { "type": "json", "path": "data.price" },
      "unit": "元",
      "alert": { "changePct": 3 }
    }
  ]
}
```

### 告警规则(5 种,可组合)
| 规则 | 含义 |
|---|---|
| `changePct` | 环比变化超过 N% |
| `above` / `below` | 高于 / 低于阈值 |
| `z` | **统计异常**(偏离均值 N 个标准差) |
| `changed` | **内容发生变更**(版本号 / 公告 / 改版) |

## 四、多页 / 登录态采集(进阶)

需要登录、或要"先拿一个值再用它取数据"的站点,用 `steps` 多步写法。

### 多步 + 变量插值 + 自动带 Cookie

```json
{
  "id": "my-stats",
  "label": "登录后的业务指标",
  "unit": "条",
  "steps": [
    {
      "url": "https://site.com/login",
      "method": "POST",
      "bodyType": "form",
      "body": { "username": "xxx", "password": "yyy" },
      "extract": { "type": "regex", "pattern": "name=\"csrf\" value=\"([^\"]+)\"" },
      "saveAs": "csrf"
    },
    {
      "url": "https://site.com/api/stats?token={{csrf}}",
      "extract": { "type": "json", "path": "data.count" }
    }
  ]
}
```

**三条规则:**
1. **Cookie 自动传递** —— 第 1 步登录产生的 `Set-Cookie` 会自动带到后续所有步骤;
2. **`{{变量名}}` 插值** —— 前面步骤 `saveAs` 存下的值,可以用在后一步的 **URL / 请求头 / 请求体**里;
3. **最后一步的 `extract`** 就是被监控的值。

### 手填 Cookie(最省事,客户最常用)

```json
{
  "id": "price",
  "label": "竞品价格",
  "url": "https://site.com/api/price",
  "cookies": { "sid": "abc123", "token": "xyz" },
  "headers": { "Authorization": "Bearer xxx" },
  "extract": { "type": "json", "path": "data.price" },
  "unit": "元"
}
```
> Cookie 从浏览器 **F12 → Application → Cookies** 复制;**请求头**每行写 `Name: value`。
> 控制台的「新增目标」里这两项都有输入框,不用手写 JSON。

### 每一步的细节可配置
每一步都支持:`url` / `method`(GET·POST) / `headers` / `body` / `bodyType`(`form`·`json`·`raw`) / `extract` / `saveAs` / `timeoutMs`。

### 排障
- 非 2xx **一律视为失败**,错误信息会带上状态码和页面提示片段,例如:
  `第 1 步返回 HTTP 401 — 用户名或密码错误`
- 详情抽屉里的「**采集配置**」会把整个步骤链摊开给你看,一眼就能发现哪一步不对。

### 不联网也能验证
```bash
node selftest.mjs        # 31 项自检,用本地模拟站点跑完整链路(不碰你的配置)
```

## 五、通知推送(出事主动找人)⭐

**这是让客户愿意按月付钱的关键** —— 客户不需要天天看报告,出事有人告诉他。

在控制台「通知推送」里配置,支持 4 种渠道:

| 渠道 | 说明 |
|---|---|
| **企业微信机器人** | 群机器人 → 添加 → 复制 Webhook 地址,免费、手机立刻收到 |
| **钉钉机器人** | 支持**加签**安全模式 |
| **邮件(SMTP)** | **零依赖手写 SMTP 客户端**,支持 465 隐式 TLS / 587 STARTTLS |
| **通用 Webhook** | POST `{title,text,summary,at}`,可对接 Server酱 等 |

### 推送时机(默认 `on-alert`)
```
on-alert  只在有告警 / 采集失败时推送   ← 推荐:不打扰,才留得住用户
always    每次采集都推送
never     不推送
```

### 推送内容长这样
```
数据监控 · 🔴 1 项采集失败

**某某公司 · 竞品监控**
🔴 1 项采集失败

❌ **官网公告页** 采集失败:请求超时(15000ms)
⚠️ **竞品A 售价** = 128 元 (+8, +6.67%) — 环比 +6.67%
⚠️ **竞品B 库存** = 12 件 (-28, -70.00%) — 低于阈值 50

时间:2026/9/22 14:46:11 ｜ 共 5 个目标
```

**配好后点「发送测试通知」即可验证能不能收到。**

## 五、交付与部署

### 打包给客户
```powershell
powershell -ExecutionPolicy Bypass -File 打包交付.ps1 -Zip
```
生成 `dist/数据监控台-<日期>/` + zip(**139 KB / 55 KB**),含交付前自检(必需文件 + 零依赖校验)。

### 客户怎么用
1. 装 Node.js(官网 LTS,一路下一步)
2. 双击 `start.bat`
3. 浏览器自动打开控制台 → 点「刷新数据」看数据

### 让它全自动
| 目标 | 做法 |
|---|---|
| 开机就监控 | 双击 `install-autostart.bat`(右键管理员运行) |
| 每天早上 8 点采集 + 推送 | 双击 `install-daily-task.bat` |
| 纯 CLI 定时 | `schtasks /create /tn "DataMonitor" /tr "node D:\path\monitor.mjs" /sc daily /st 08:00` |
| Linux / macOS | `0 8 * * * cd /path && node monitor.mjs >> logs/run.log 2>&1` |

## 六、API(开发者对接)

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/state` | 当前状态(从历史快照还原,不触发采集) |
| POST | `/api/run` | 执行一次全量采集(+按配置推送通知) |
| POST | `/api/run/:id` | 只重采某一个目标 |
| POST | `/api/run-preview` | 测试一个目标能否取到值(不落库、不改配置) |
| GET | `/api/history?id=&limit=` | 单目标历史记录 |
| POST | `/api/targets` | 新增监控目标 |
| PUT | `/api/targets/:id` | 修改目标 |
| DELETE | `/api/targets/:id` | 删除目标 |
| GET / PUT | `/api/notify` | 读取 / 保存通知配置 |
| POST | `/api/notify-test` | 用假数据测试所有已启用渠道 |
| GET | `/api/export.csv` `.json` | 导出数据 |
| GET | `/api/health` | 健康检查 |

**服务端设计要点(开发者视角)**
- 零依赖(`node:http`),无框架、无构建步骤
- **顺序采集** —— 天然限流,不会把对方站点打挂
- **并发保护** —— 已有采集进行中时再次请求返回 `409`,不重复跑
- **失败隔离** —— 单个目标失败不影响其余目标,错误进报告
- **配置校验** —— id/label/url/extract.type 全校验,重名 id 拒绝(409)
- **无状态服务** —— 历史快照(`data/*.jsonl`)是唯一事实来源,重启不丢
- **端口占用友好提示** —— 重复启动时提示「服务可能已在运行」而不是崩掉
- **控制台输出全 ASCII** —— 避免客户机 GBK 控制台乱码(中文都在浏览器里)

## 九、接单参考

> **不要卖"代码",卖"每天早上的那份报告 + 出事时的那个提醒"。**

| 服务形态 | 报价区间(参考) | 说明 |
|---|---|---|
| 一次性搭建(1–3 目标) | 500–2000 元 | 交付脚本 + 配置 + 教会运行 |
| 一次性搭建(10+ 目标) | 2000–8000 元 | 含多页解析、反爬处理 |

**为什么按月收能成立:** 数据源会变、需求会加、脚本会坏 —— 客户买的是"持续有人管"。

## 十、合规红线

- ✅ 只采集**公开数据**;**不采集个人信息**(手机号 / 身份证 / 住址等)
- ✅ 遵守目标站点 `robots.txt` 与使用条款;**控制频率**(本项目自带顺序采集 + 退避重试)
- ❌ 不绕过登录 / 验证码 / 付费墙
- ❌ 不做高频请求导致对方服务受影响
- ❌ 不转卖、不公开客户的监控数据
- ⚠️ 涉及个人信息的场景,**一律不接**

## 十一、技术结构

```
data-monitor/
├── server.mjs             本地服务:API + 静态托管(零依赖 node:http)
├── monitor.mjs            CLI:采集 → 报告 → 推送(给定时任务用)
├── config.json            监控配置 + 通知配置(客户只改这个)
├── lib/
│   ├── fetch.mjs          抓取:超时 / 指数退避重试 / 受控并发
│   ├── extract.mjs        提取:json / regex / length / text + 内容指纹
│   ├── store.mjs          历史存储(JSONL)+ 统计(均值 / 标准差)
│   ├── collect.mjs        采集核心(CLI 与 API 共用)+ 告警判定
│   ├── report.mjs         静态报告:HTML + CSV
│   └── notify.mjs         通知:企业微信 / 钉钉 / 邮件(手写 SMTP)/ Webhook
├── public/index.html      交互式控制台(单文件,无框架无构建)
├── start.bat / start.sh   一键启动
├── install-*.bat          开机自启 / 每日任务注册
├── 打包交付.ps1            生成交付包 + 自检
└── 客户使用说明.txt         给客户的说明书
```
